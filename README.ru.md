# O-Zone Online Store

[English](README.md) | **Русский**

Витрина интернет-магазина без фреймворка на чистом JavaScript (ES-модули) и SCSS, собранная Webpack 5 по собственному конфигу.

## Возможности

- 28 карточек товаров из JSON, у товаров по акции плашка «Hot Sale».
- Поиск при вводе, меню категорий, цена «от / до» и чекбокс «Акция» — всё применяется одновременно.
- Заголовок над сеткой показывает текущую категорию и число найденных товаров; если ничего не нашлось, вместо пустой сетки выводится подсказка.
- Корзина в `localStorage`: добавление и удаление, счётчик в шапке и общая сумма. «Оформить заказ» отправляет корзину на тестовый API [jsonplaceholder](https://jsonplaceholder.typicode.com/).
- Адаптивная сетка; фильтр по цене стоит в боковой колонке от 992 px, на экранах уже он скрыт.

## Архитектура

```
db/db.json ──► getData.js ──► state.js: applyFilters() ──► renderGoods.js ──► сетка карточек
                                   ▲                              └──► changeInfo.js (заголовок)
        search.js · catalog.js · filter.js  (каждый меняет своё поле состояния)
```

1. [src/index.js](src/index.js) подключает SCSS и запускает модули; [search.js](src/modules/search.js), [catalog.js](src/modules/catalog.js) и [filter.js](src/modules/filter.js) записывают запрос, категорию, диапазон цен и флаг акции в общий объект [state.js](src/modules/state.js).
2. `applyFilters()` прогоняет товары из [getData.js](src/modules/getData.js) сразу через все функции [filters.js](src/modules/filters.js); [renderGoods.js](src/modules/renderGoods.js) рисует карточки, [changeInfo.js](src/modules/changeInfo.js) обновляет заголовок.
3. [cart.js](src/modules/cart.js) хранит корзину в `localStorage` и выводит её через [renderCart.js](src/modules/renderCart.js).

### Сборка Webpack

| Часть | Зачем |
| --- | --- |
| `sass-loader` → `css-loader` → `MiniCssExtractPlugin.loader` | Выполняется справа налево: SCSS компилируется, `url()` шрифтов и картинок становятся зависимостями, CSS выносится в отдельный файл и грузится параллельно со скриптом |
| `HtmlWebpackPlugin` + `html-loader` | `index.html` — шаблон; плагин вставляет CSS и JS с хешами, html-loader пропускает фавиконки через webpack |
| Asset modules (`asset/resource`) | Картинки, шрифты и манифест копируются в `dist/`, в код подставляется итоговый URL; у регулярки флаг `/i`, потому что шрифты `.OTF` |
| `CssMinimizerPlugin` | Сжимает CSS в prod; `'...'` в `minimizer` оставляет Terser для JS по умолчанию |
| `CopyPlugin` | Копирует `img/goods/` как есть: пути к картинкам записаны строками в `db.json`, webpack их не видит, и хеши им добавлять нельзя |

- **Development:** `source-map` (исходные JS и SCSS в DevTools), без минификации, `publicPath: '/'`.
- **Production:** Terser и cssnano, `[contenthash]` в именах файлов для долгого кеширования, `publicPath: '/webpack-ozon/'`, потому что GitHub Pages отдаёт проект из подпапки.

### Ключевые решения

- **Данные как статический ассет.** `new URL('../../db/db.json', import.meta.url)` заставляет webpack выложить JSON отдельным файлом с хешем, поэтому код интенсива по-прежнему загружает его через `fetch`, а изменился только [getData.js](src/modules/getData.js).
- **Одно состояние фильтров.** Вместо того чтобы каждый обработчик фильтровал полный список, модули используют общий объект состояния и одну `applyFilters()`, поэтому фильтры складываются.

## Что изменено позже

- **Сборка.** На интенсиве webpack работал на настройках по умолчанию, SCSS собирался расширением редактора Live Sass Compiler, а `dist/` и CSS лежали в репозитории. Я написала конфиг, описанный выше, убрала результаты сборки из git, добавила `package-lock.json` и настроила деплой через GitHub Actions.
- **Данные и картинки.** Firebase-база интенсива теперь отвечает `401`, поэтому товары загружаются из `db/db.json`. Фото товаров с CDN Ozon тоже больше не открываются; я заменила их локальными SVG-заглушками (меньше 1 КБ каждая: цвет категории, иконка типа товара, название модели).
- **Фильтры складываются.** Раньше при выборе категории и последующем вводе цены категория сбрасывалась; теперь у всех фильтров общее состояние.
- **Меню категорий.** Вместо `<li>` с обработчиками клика — `<button>` с `data-category` и `aria-pressed`, пункт «Все товары», подсветка выбранного, работа с клавиатуры.
- **Заголовок и пустой результат.** Текущая категория и число товаров со склонением через `Intl.PluralRules`; использованы стили `.category-title`, которые были в SCSS с интенсива, но не применялись.

## Запуск

Нужен Node.js 22.15+ (этого требуют webpack-dev-server 6 и sass-loader 17).

```bash
npm install
npm run dev          # http://localhost:8080
npm run build        # dist/; раздавать по пути /webpack-ozon/, через file:// не откроется
```

## Деплой

Сайт опубликован на GitHub Pages через GitHub Actions: каждый пуш в `main` запускает `npm ci` и `npm run build` и публикует `dist/`. Я выбрала Actions, а не пакет `gh-pages`, чтобы результаты сборки не хранились ни в одной ветке, а сайт всегда собирался из `main`.

## Известные ограничения

- Счётчик корзины в шапке не обнуляется после «Оформить заказ» до перезагрузки страницы, а заказ можно отправить из пустой корзины.
- Границы цены не включаются (`>` и `<`): при фильтре «от 3624» товар за 3624 ₽ не показывается.
- Иконка закрытия корзины чёрная, потому что в SVG написано `fill='005bff'` без `#`; шрифт `GTEestiProDisplay` используется, но не подключён; манифест фавиконок пустой.
- Корзина открывается ссылкой `href="#"`, у поля поиска нет `label`, а модальное окно корзины и меню категорий не закрываются по Esc.

## Что бы я улучшила

- **Загружать данные один раз.** `getData()` вызывается на каждое нажатие клавиши, хотя товары достаточно загрузить один раз и держать в памяти.
- **Состояния ошибки и загрузки.** Если данные не пришли, страница остаётся пустой — именно так и было, когда Firebase начал отвечать 401.
- **Безопасный рендер.** Карточки собираются через `innerHTML` из шаблонных строк; с настоящими данными нужно экранирование или `<template>`.
- **Меньше внешних зависимостей.** Bootstrap подключён целиком ради одной сетки, хотя хватило бы CSS Grid.
